# 淘寶訂單批量匯出 v3

[English](readme.md) · [安裝／更新淘寶腳本](https://github.com/DF-wu/taobaoOrderExporter/raw/main/taobaoOrderExporter.user.js) · [安裝／更新聖天預報腳本](https://github.com/DF-wu/taobaoOrderExporter/raw/main/shengtian-predeclare.user.js)

從淘寶「已買到的寶貝」直接讀取訂單及物流資料，匯出一個 **XLSX** 或 **JSON**。不再操作官方匯出按鈕，程式沒有十頁上限，也可取得尚未確認收貨訂單的物流。

## 使用方法

1. 在 Brave／Chrome／Firefox 安裝 Tampermonkey 或 Violentmonkey，開啟上方腳本連結安裝或更新。
2. 登入淘寶，進入 [已買到的寶貝](https://buyertrade.taobao.com/trade/itemlist/list_bought_items.htm)。
3. 右下角出現匯出面板。選擇訂單範圍，輸入起始頁；**截止留空會抓到最後一頁**，也可填入指定頁碼。請求間隔預設 **5 秒**，可調為 2–120 秒。
4. 按「開始擷取」。資料會持續儲存在瀏覽器 IndexedDB，可隨時停止或下載。
5. 完成後按「下載 XLSX」或「下載 JSON」。檢查面板的物流待補查數與檔案中的 `Errors`。

物流來源依序使用新版列表的包裹資訊、「查看物流」頁的 API，以及訂單詳情 API。多包裹會逐一讀取，保留公司、單號、商品對應與來源，不把第一個包裹的單號套用到整筆訂單。

「補查物流軌跡」會為已有單號的訂單再讀取物流頁，速度較慢。單號與物流公司預設就會擷取。付款資訊、商品規格、數量與退款狀態也會保留。

集運運費等訂單若在官方詳情明確標示「无需物流」，會記為 `not_required`；交易已關閉、物流與詳情均無包裹紀錄時記為 `no_package`。兩者的依據都列於「物流說明」，不再混入物流查詢失敗。單純「暂无单号」仍需補查。

## 中斷與重試

- **停止**：中止目前流程，保留已儲存的訂單及斷點。
- **斷點續抓**：重新整理或重新開啟頁面後，從上次尚未完成的頁面繼續；以主訂單號去重。
- **中止原因**：最近一次錯誤隨斷點保存，重新整理仍可查看；多包裹中途要求驗證時，已查到的包裹先儲存再停止。
- **重試物流**：補查「物流待補查」（pending／partial／failed 或有錯誤）與「擷取時未發貨」的訂單。先重讀訂單原本所在的頁面取得最新狀態；若新訂單使頁碼移動，或訂單已離開當初篩選的分頁（例如出貨後離開「待發貨」），改用訂單號直接查物流，不必重新擷取整個範圍。原頁若顯示訂單已變成其他狀態（例如交易关闭），依新狀態處理，與重新擷取相同。查詢失敗不會清掉已知單號；直接查詢失敗時不會降級（未發貨維持未發貨、完整物流維持完整），並把原因列入 Errors。讀頁遇到網路或格式錯誤時會停止，不逐筆白跑。
- **登入或驗證要求**：流程會暫停；若有官方驗證網址，面板會顯示連結。完成後回來續抓，物流補查可再按「重試物流」。
- **清除本機資料**：只清除此工具目前帳號的資料及斷點；先下載備份。

重新擷取範圍會合併資料，不會刪除之前其他範圍的訂單。未發貨與失敗的物流會重新查詢；「交易成功／交易关闭」且狀態未變的訂單直接沿用已完整的物流，不再逐筆查詢（勾選「補查物流軌跡」時仍會重讀軌跡），其他狀態只沿用一小時內驗證過的結果。列表包裹不完整時先併入先前取得的單號：補查失敗標為 partial 並記錄錯誤；中途停止則維持 pending，等續抓或重試物流再查。兩者都不會清空已知單號。開始新範圍時若有未完成斷點，會先詢問是否取代。跨分頁鎖防止同帳號多個任務同時寫入。

### 物流更新後要按哪個按鈕？

| 情況 | 建議操作 |
| --- | --- |
| 上次擷取時尚未發貨或查不到物流，現在已有單號 | 按 **重試物流**。只處理未完成的訂單，頁碼移動也查得到。 |
| 單號已取得，想更新運送中的物流軌跡 | 勾選「補查物流軌跡」，範圍選「待收貨」，按 **開始擷取**。 |
| 想同時更新交易狀態、商品或加入新訂單 | 按 **開始擷取** 重跑該範圍；已結束交易的完整物流會沿用，不會全部重查。 |
| 擷取中途停止或被要求驗證 | 按 **斷點續抓**。 |

以訂單號直接補查時，物流 API 不提供交易狀態，「訂單狀態」欄位會保留上次列表的文字；需要最新狀態時重新擷取該範圍。

列表、物流、詳情與連線重試共用同一請求間隔，逐筆執行，不平行送出。間隔設定隨斷點保存；停止後可調整再續抓。淘寶仍可能依帳號或時段限流，收到限流／驗證回應時會立即暫停，不自動重試；可先增加間隔再繼續。

## 輸出與隱私

XLSX 分成 Orders（主訂單）、Items（商品）、Packages（包裹）、Errors、Metadata 五張表。JSON 保留相同結構，適合 Python 或資料庫處理。詳見 [資料格式](docs/data-format.md)。

腳本不依賴 CDN 或額外函式庫，不上傳資料到第三方。資料只留在淘寶來源的本機 IndexedDB 與你下載的檔案；不同登入帳號使用不同資料庫。不會匯出登入 cookie 或收件人地址。物流軌跡本身可能包含快遞員的聯絡資訊。

請維持登入並保持頁面開啟；瀏覽器休眠、分頁凍結或關閉會暫停執行。不同分頁篩選或新增訂單可能改變頁碼；頁碼代表擷取當下的排序，並非淘寶提供的歷史快照。此工具沒有自行增加頁數限制，仍受淘寶帳號可見資料範圍與服務回應影響。

## 聖天集運預報

[聖天預報 userscript](https://github.com/DF-wu/taobaoOrderExporter/raw/main/shengtian-predeclare.user.js) 可在 [我的包裹](http://member.stjh168.com/Member/MyPack) 頁貼上／匯入 JSON，核對目前包裹及歷史紀錄後逐筆預報。支援簡單包裹清單、既有預報計畫及本工具的淘寶 JSON；品名可在預覽中核對及修改。已有紀錄會保留，提交後回讀核對，逾時或未知結果不盲目重送。同源 API 提交避開官方前端的 alert 與整頁重整，不會全域關閉網站彈窗。安裝後不需要 debug port 或 Node。詳見 [安裝、JSON 格式與例外處理](docs/shengtian-userscript.md)。

`1.1.0` 起可設定自己的 OpenAI Chat Completions 相容 API，生成簡短品名與備註建議。支援自訂網址、模型、金鑰及提示詞；生成前先只讀核對已預報與歷史紀錄，建議先預覽，套用後仍須核對才會預報。金鑰預設只留在分頁記憶體，也可選擇存於腳本管理器；不放入網站資料庫或匯出結果。詳見 [自訂 LLM API](docs/shengtian-userscript.md#自訂-llm-api)。

[聖天預報 skill](skills/shengtian-predeclare/SKILL.md) 可讓 agent 將匯出的 XLSX／JSON 與已登入的聖天帳號核對，保留已有及歷史紀錄、替未報包裹預報、自動按掉提交彈窗，並核對實際儲存內容。附有透過既有 Brave debug 連線執行的 Node／Python 工具，不需額外套件。簡短品名由 agent 核對商品與規格後產生；淘寶腳本本身不會自動上傳訂單。

## 開發與驗證

```sh
node --check taobaoOrderExporter.user.js
node --check shengtian-predeclare.user.js
node --test tests/exporter.test.cjs
node --test tests/shengtian.test.mjs tests/shengtian-userscript.test.cjs tests/shengtian-llm.test.cjs
python tests/test_shengtian_export.py
```

測試使用 Node 24 與 Python 3 標準函式庫，不需要 npm install。涵蓋多包裹、長 ID、超過十頁、停止續抓、物流補查（未發貨轉出貨、頁碼移動、失敗不清空）、錯頁、登入驗證、儲存失敗、JSON 及 XLSX 的 ZIP／XML 驗證。測試資料完全合成，不含真實訂單。

新版 API 觀察基準：2026-10-26。實作直接使用淘寶頁面的 MTOP SDK；若官方變更資料結構，程式會顯示錯誤，請勿將缺漏的物流當成未發貨。
